A different starting point

不是给代码聊天框
加几把工具。

真正的 coding agent 要持续做判断：读什么、改哪里、何时请求许可、怎样证明结果。 mx-claw 把这些判断变成可见、可暂停、可恢复的执行链。

你看到的不是一段“已完成”的文本，而是从项目上下文到验证结果的完整证据。

Capabilities

从理解仓库到交付结果。

不把所有能力一次性塞给模型。核心工具直接可用，扩展工具按需发现；每项动作都经过同一套权限与边界。

01 / EXECUTION

真正的工具循环

搜索、读取、编辑、命令和多模态输入组成连续循环。只读工具可并行，写操作保持顺序和授权。

  • read_file
  • edit_file
  • run_command
02 / CONTEXT

理解项目的运行规则

自动加载工作区规则，压缩长会话时保留目标与协议结构，并在修改后要求执行项目验证命令。

AGENTS.md context / frozen
03 / MEMORY

会积累，但不会擅自决定

长期记忆与可复用 Skill 都从真实轨迹中形成。候选内容经过审核后才影响后续会话。

USER.md MEMORY.md SKILL.md
04 / RECOVERY

会话不在刷新后消失

消息、事件、审批和任务进度写入 SQLite。客户端断线后可以按照事件序号继续读取。

05 / EXTENSIBILITY

给模型更多工具，不把上下文一次占满。

MCP、LSP 和后台调查工具按需发现。最多四个只读子 Agent 并行工作，父会话只接收结构化摘要。

MCP LSP SKILL SUBAGENT agent
The loop

每一步都留下证据。

01

Bind

绑定工作区

选择一个本地项目。文件访问、命令目录和项目记忆都被限制在这个边界内。

02

Delegate

描述要完成的事

从 CLI 或 Web 发起任务。模型读取真实文件，形成任务进度，并在需要时请求许可。

03

Prove

审阅结果，而不是猜测

检查工具结果、修改摘要与验证退出码。失败就停在失败处，不把不确定包装成完成。

prompt context tools approval verified
Permission by design

能力越大，
边界越要具体。

审批不是最后一道装饰。路径限制、危险命令拦截、沙箱和审计在批准之后仍然生效。

系统边界不会被 allow-all 关闭。

permission mode mutation policy
default 变更前逐次询问 ASK
plan 只读分析与规划 READ
accept-edits 自动接受工作区编辑 EDIT
unattended 无法确认时直接拒绝 DENY
allow-all 二次确认后放行常规操作 OPEN

allow-all 也不会关闭显式 deny、灾难命令拦截、路径边界和命令沙箱。

Questions

开始之前，
你可能想知道。

我的代码会上传到 mx-claw 的服务器吗？

会话、记忆、Skill 和权限数据默认保存在本机。模型请求会发送到你配置的模型服务， 因此请选择符合个人或团队数据要求的 Provider。mx-claw 不会额外搭建一个中转云服务。

必须配置 API Key 才能体验吗？

不需要。mx-claw 默认使用离线 Demo，不会主动发起模型请求。 执行真实任务时再配置 OpenAI-compatible Provider。

Agent 可以直接执行任何命令吗？

不可以。写操作和高风险命令会根据权限模式请求审批；灾难命令会被硬拒绝； 命令还受超时、CPU、文件大小、输出和平台沙箱限制。

CLI 和 Web 是两套不同的会话吗？

不是。它们共享同一套 Agent Core、SQLite 会话、事件、权限和任务状态。 两个进程可以观察同一会话；同一时刻只有一个 turn 能取得执行租约。

支持哪些操作系统？

macOS 和 Linux 支持原生命令沙箱；Windows 支持文件操作，但命令默认 fail closed，可以显式使用 Docker 沙箱。

当前是开源软件吗？

当前版本是专有软件。npm 分发包允许按许可证安装和运行；复制、再分发、商业托管或二次开发前， 请先阅读仓库中的许可证。
